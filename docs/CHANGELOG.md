# Changelog

## v2.0 — 2026-11-03

- Clarified explicit adoption, immutable version pins, actual instruction authority and standing permission.
- Shortened routing and required targeted reads, clean text reuse, fresh reasoning from verified state and no repeated plans or source dumps.
- Made one implementer the default, with justified bounded specialists and capability-based environment/model choices.
- Added five-minute changed-work checkpoints, a ten-minute synchronization stop boundary, safe WIP backup, exact remote verification and explicit offline handling.
- Separated checkpoint, feature and same-revision merge/release verification; required truthful functionality and relevant accessibility, responsive and visual checks.
- Consolidated continuation into one current status with receipts and the user's five-field STATUS format, including honest full-task time estimates and Europe/Berlin ETA.
- Added a product-owned recovery validation plan and retained historical migration and ownership intent.

This revision changes reusable policy. It does not itself install a global agent configuration, implement product checkpoint automation, validate a product recovery drill or deploy a product.

## Earlier policy baseline

The previous modular policy used v1.1 markers and documented the earlier corporate, division, design-system and product repository separation. The [migration manifest](migration-manifest.md) remains a historical record of that reorganization.
